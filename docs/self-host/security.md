# Security model

What a self-hosted install enforces, what's left to the operator, and the
known limits. Mechanisms are described in
[architecture.md](../architecture.md); reporting a vulnerability is in
[SECURITY.md](../../SECURITY.md).

## Enforced

### Network edge

| Control | |
| --- | --- |
| Published ports | Caddy only: 80 (ACME and HTTPS redirect), 443, 6697 (IRC over TLS). No access logs |
| TLS | all external traffic, Let's Encrypt certificates. A plaintext IRC client gets a message to use TLS and nothing else |
| IRC accounts | no self-registration; accounts come from console invites; SASL required |
| First-run setup | requires the setup code from the console's log (host access); wrong codes are rate-limited |

### Authentication

| Control | |
| --- | --- |
| Two-step sign-in | required for the owner and anyone with org-wide change permissions (passkey or TOTP) before any other action; optional for others |
| Changes require two-step | for accounts with two-step on or required, GuildServ accepts changes (hiring, approvals, access, budgets, pausing) only from the console and its web chat. IRC clients, which authenticate with a password alone, are read-only for them |
| Passwords | bcrypt, in Ergo; sign-in attempts rate-limited |
| Web chat | one-minute tokens for one account; the connection closes on sign-out; same-origin only |
| Owner recovery | `reset-owner` requires a shell on the host |
| Removal from the org | ends all the person's IRC sessions, including always-on ones, and disables their password |
| Private teams | channels contain only the team; others are removed when a team goes private; channel registration can't be pre-empted or taken over |

### Host

| Control | |
| --- | --- |
| Container privileges | all capabilities dropped except those required; `no-new-privileges`. The console, Ergo, the runner and egress run as non-root on read-only root filesystems |
| Networks | the database is on an internal network shared only with the console and the runner. Each has its own database login, without access to the other's database |
| Secrets | generated by `init.sh`, never printed; `.env` mode 600 |
| Model keys, connector tokens | sealed with `GUILDNET_PLATFORM_KEY`; model keys reach the runner over TLS (the console's own CA) and are held in memory only |
| GitHub App key | never leaves the console; the runner gets per-call tokens, scoped to the call's repositories and permissions |
| Git credentials | sealed in the console, bound to each repository's address. Desks get the read credential only; the runner gets the push credential per push ([git.md](git.md)) |

### Agents

| Control | |
| --- | --- |
| Who agents work for | an agent works with its team's repositories and the company's connected services for whoever asks it, so only people in the org wake agents. A private team's agents (and those of teams inside it) take asks only from people in the team's channel: its members, the leads above it, and the owner. Guests wake no agents until the owner allows it (`COMPANY GUESTS on`) |
| Private teams' tools | a repository or connected service a private team uses can be given to another team only by someone in the private team, or the owner |
| Approvals | merging a pull request requires a person's approval; connector writes too, unless their policy allows them |
| Untrusted input | a write to one service shortly after reading another (Linear after a desk or GitHub, Notion after Linear, …) requires approval, whatever its policy. A Managed Agents desk's own tools (web fetch and search, its shell) count as reading from outside. The team's code counts as one source: work read in one of its repositories may go to another without asking |
| Spending | daily caps per agent and per network |
| Desks | gVisor, an internal network, an allowlist proxy, and the desks' firewall ([desks.md](desks.md#isolation)) |

## Operator responsibilities

| Area | |
| --- | --- |
| Host | keep the OS and Docker patched (on Ubuntu, unattended upgrades). Open only 80, 443 and 6697; SSH by key, to your addresses only |
| Root | root, or the Docker socket, gives every secret and all data. sandboxd holds the socket: it acts only on console-signed tokens, but it's root-equivalent |
| `.env` and backups | they contain every secret: keep them private; encrypt backups that leave the host; keep copies off it |
| Upgrades | security fixes ship in releases; upgrade promptly ([operations.md](operations.md#upgrading)) |
| Images | each release's images are signed by this repository's release workflow, from a commit of main whose CI passed. To check one: `cosign verify ghcr.io/guildnet-chat/platform:<release> --certificate-identity-regexp '^https://github.com/guildnet-chat/guildnet/.github/workflows/release.yml@refs/tags/' --certificate-oidc-issuer https://token.actions.githubusercontent.com` |
| Admins | the owner and org-wide admins can change everything, including which tools run without approval |
| Model providers | set a spending limit with each provider |
| Email | send from a domain with SPF and DKIM |
| Desks without gVisor | share the host kernel: a desk escape reaches the host |
| Desk egress | anything a desk can read can be uploaded to an allowed host ([desks.md](desks.md#residual-risk)) |
| Git read credentials | they reach desks: make them read-only, one repository each ([git.md](git.md#residual-risk)) |
| Monitoring | read the logs, or report faults to Sentry or GlitchTip ([configuration.md](configuration.md#fault-reports)) |

## Limits

| Limit | |
| --- | --- |
| Internal TLS | only the broker and sandboxd use TLS; console, runner, Ergo and Postgres traffic is plaintext on Docker's private networks on one host |
| Password-only IRC access | an IRC client with someone's password (no second step) reads what they can read: their channels and private messages. It can't change the org |
| Single host | no failover; restore a backup on another host ([operations.md](operations.md#restore)) |
| Data at rest | chat history (kept 90 days by Ergo) and the databases are unencrypted on disk, apart from sealed secrets. Use disk encryption if required |
