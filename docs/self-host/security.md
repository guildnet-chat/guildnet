# Security model

What a self-hosted install enforces, what's left to the operator, and the
known limits. Mechanisms are described in
[architecture.md](../architecture.md); reporting a vulnerability is in
[SECURITY.md](../../SECURITY.md).

## Enforced

### Network edge

| Control | |
| --- | --- |
| Published ports | Caddy only: 80 (ACME and HTTPS redirect), 443, 6697 (IRC over TLS). No access logs |
| TLS | all external traffic, Let's Encrypt certificates. A plaintext IRC client gets a message to use TLS and nothing else |
| IRC accounts | no self-registration; accounts come from console invites; SASL required |
| Flooding | after a burst of 30 commands, a client is slowed to 5 a second (Ergo's fakelag), not disconnected. GuildServ isn't slowed |
| First-run setup | requires the setup code from the console's log (host access); wrong codes are rate-limited |

### Authentication

| Control | |
| --- | --- |
| Two-step sign-in | required for the owner and anyone with org-wide change permissions (passkey or TOTP) before any other action; optional for others |
| IRC app passwords | for accounts with two-step on or required, IRC apps sign in only with app passwords, made on the account page and shown once; the account's own password signs in to nothing over IRC. Revoking one ends the account's IRC sessions. Anyone may use them, to keep their password out of IRC apps |
| Changes require two-step | for accounts with two-step on or required, GuildServ accepts changes (hiring, approvals, access, budgets, pausing) only from the console and its web chat. IRC apps, which sign in with one factor (an app password), are read-only for them |
| Passwords | people's are the console's (bcrypt, as Ergo hashes them). Ergo asks the console about every person's IRC login, and its answer is final (GuildNet's patch to Ergo, `deploy/ergo/authoritative-auth-script.patch`). A password from before, still in Ergo, moves to the console at its first sign-in. Agents' passwords are Ergo's |
| Guessing | held back the same on IRC and in the console: 5 wrong passwords for one person from one address (an IPv6 /64) hold it back for 15 minutes, and so do 20 for any accounts, except for people it has signed in as in 30 days; 20 in an hour, from anywhere, hold back every address that hasn't signed in as the person in 30 days, for an hour, and the owner is emailed |
| Opening a console from the home page | the link asks "Open acme as ada?" and signs in only when its button is pressed, on the console's own page: a link someone else made, and sent, can't sign a browser in as them unawares. Two-step sign-in still asks its second step |
| IRC self-service | nobody changes their password, adds a certificate or unregisters their account over IRC; operators (GuildServ) still can |
| Console sign-ins | end after a day unused, and a week on however they're used; a new password, removal from the org or turning on two-step ends the person's others |
| Passkeys | a passkey whose count of uses goes back (a copy) is refused, and the owner is emailed |
| Owner alerts | the owner is emailed when a password reset link is made (by someone else) or used, and when anyone turns on two-step sign-in or adds a passkey or app to it |
| Web chat | one-minute tokens for one account; the connection closes on sign-out, or once the sign-in has ended; same-origin only |
| Owner recovery | `reset-owner` requires a shell on the host |
| Removal from the org | ends all the person's IRC sessions, including always-on ones, and disables their password |
| Private teams | channels contain only the team; others are removed when a team goes private; channel registration can't be pre-empted or taken over. Their leads, budgets, repositories, connectors, goals and numbers are shown only to people in them (and the leads above them) and the owner, in GuildServ, the console and the API: others see only that they're there, and private |

### Host

| Control | |
| --- | --- |
| Container privileges | all capabilities dropped except those required; `no-new-privileges`. The console, Ergo, the runner and egress run as non-root on read-only root filesystems |
| Networks | the database is on an internal network shared only with the console and the runner. Each has its own database login, without access to the other's database |
| Secrets | generated by `init.sh`, never printed; `.env` mode 600 |
| Model keys, connector tokens | sealed with `GUILDNET_PLATFORM_KEY`; model keys reach the runner over TLS (the console's own CA) and are held in memory only |
| GitHub App key | never leaves the console; the runner gets per-call tokens, scoped to the call's repositories and permissions |
| Git credentials | sealed in the console, bound to each repository's address. Desks get the read credential only; the runner gets the push credential per push ([git.md](git.md)) |

### Agents

| Control | |
| --- | --- |
| Who agents work for | an agent works with its team's repositories and the company's connected services for whoever asks it, so only people in the org wake agents. A private team's agents (and those of teams inside it) take asks only from people in the team's channel: its members, the leads above it, and the owner. Guests wake no agents until the owner allows it (on the People page, or `COMPANY GUESTS on`) |
| What guests see | their channels and the agents in them: the runner's API and GuildServ refuse guests the org chart, people, teams, goals, budgets, spend and the log, and the console doesn't link to them |
| Private teams' tools | a repository or connected service a private team uses can be given to another team only by someone in the private team, or the owner |
| Approvals | merging a pull request requires a person's approval; connector writes too, unless their policy allows them |
| Agents' own pull requests | an agent pushes only to branches named for it (`kai/…`), and closes only pull requests the GitHub App's bot opened, from the repository itself, on its branch: nothing anyone writes into a pull request makes it the agent's |
| Untrusted input | a write to one service shortly after reading another (Linear after a desk or GitHub, Notion after Linear, …) requires approval, whatever its policy. A Managed Agents desk's own tools (web fetch and search, its shell) count as reading from outside. The team's code counts as one source, and its public GitHub repositories as another, since anyone may have written what's in them (a pull request from a fork, an issue): work read in a private repository goes to a public one only with approval, and the other way round; within either, without asking |
| Spending | daily caps per agent and per network |
| Desks | gVisor, an internal network, an allowlist proxy, and the desks' firewall ([desks.md](desks.md#isolation)) |
| Desk storage | with `GUILDNET_DESK_FILES` on XFS, each network's desks' files are limited, in all ([desks.md](desks.md#storage)); without it, a desk can fill the host's disk |

## Operator responsibilities

| Area | |
| --- | --- |
| Host | keep the OS and Docker patched (on Ubuntu, unattended upgrades). Open only 80, 443 and 6697; SSH by key, to your addresses only |
| Root | root, or the Docker socket, gives every secret and all data. sandboxd holds the socket: it acts only on console-signed tokens, but it's root-equivalent |
| `.env` and backups | they contain every secret: keep them private; encrypt backups that leave the host; keep copies off it |
| Upgrades | security fixes ship in releases; upgrade promptly ([operations.md](operations.md#upgrading)) |
| Images | each release's images are signed by this repository's release workflow, from a commit of main whose CI passed. To check one: `cosign verify ghcr.io/guildnet-chat/platform:<release> --certificate-identity-regexp '^https://github.com/guildnet-chat/guildnet/.github/workflows/release.yml@refs/tags/' --certificate-oidc-issuer https://token.actions.githubusercontent.com` |
| Admins | the owner and org-wide admins can change everything, including which tools run without approval |
| Model providers | set a spending limit with each provider |
| Email | send from a domain with SPF and DKIM |
| Desks without gVisor | share the host kernel: a desk escape reaches the host |
| Desk egress | anything a desk can read can be uploaded to an allowed host ([desks.md](desks.md#residual-risk)) |
| Git read credentials | they reach desks: make them read-only, one repository each ([git.md](git.md#residual-risk)) |
| Monitoring | read the logs, or report faults to Sentry or GlitchTip ([configuration.md](configuration.md#fault-reports)) |

## Limits

| Limit | |
| --- | --- |
| Internal TLS | only the broker and sandboxd use TLS; console, runner, Ergo and Postgres traffic is plaintext on Docker's private networks on one host |
| Password-only IRC access | an IRC client with someone's password (no second step) reads what they can read: their channels and private messages. It can't change the org |
| Single host | no failover; restore a backup on another host ([operations.md](operations.md#restore)) |
| Data at rest | chat history (kept 90 days by Ergo) and the databases are unencrypted on disk, apart from sealed secrets. Use disk encryption if required |
